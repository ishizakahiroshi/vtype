# Chrome ウェブストア 提出文書（v0.2.0・日本語・下書き）

ダッシュボードの「単一用途」「権限の正当化」「データ利用」の各欄へ貼る文面と、審査担当者向けのメモ。
v0.2.0 の提出時に使う下書き。**v0.1.0 の審査が終わるまでは、ストアの掲載もこの文面も提出しない**。
変わらない欄（単一用途の前半・既存の権限の説明）は v0.1.0 の文書と同じ文を使う。

## 審査担当者向けメモ

v0.1.0 からの変更点:

- 入力モード（通常 / 英語 / カタカナ）と置き換え表。認識した文字をパッケージ内の辞書でカタカナへ変換し、
  利用者が登録した「A を B にする」の組を当てる。どちらもブラウザの中だけで行う
- 不具合の報告: 設定ページの「報告フォームを開く」は GitHub の新しい issue の入力画面を、版・OS・
  ブラウザ名を埋めて新しいタブで開くだけで、自動では何も送らない

権限は v0.1.0 から増えていません（`optional_permissions` もありません）。設定ページには、別のアプリである
デスクトップ版の案内とリンクが 1 行あるだけで、拡張機能はデスクトップ版と通信しません。

## 単一用途

Web ページのテキスト入力欄へ、音声で文字を入力すること。

## 権限に関する説明

`offscreen` / `storage` / content script の `http://*/*` と `https://*/*` の説明は v0.1.0 と同じ文を使う。
権限は増えない。`storage` の説明にだけ次を足す:

- `storage` の保存項目に、入力モード（`inputMode`）と置き換え表（`replacements`・`chrome.storage.local`）を
  足します

## データ取り扱い

v0.1.0 の内容に次を足す。

- 置き換え表: 利用者が自分で登録した語の組。ブラウザ内（`chrome.storage.local`）にだけ保存します
- 不具合の報告: ブラウザで GitHub の入力画面を開くだけです。送信は利用者が画面上で行い、拡張機能は
  何も送りません

## テスト観点

v0.1.0 の 1〜7 に加えて:

1. 設定ページの入力モードを「カタカナ」にして話すと、欄に全角カタカナで入ること。モードは
   切り替えたまま残り、ブラウザを再起動しても変わらないこと
2. 置き換え表に 1 行足すと、次に認識した文字から反映されること
3. 権限: chrome://extensions の詳細で、権限が v0.1.0 と同じ（任意の権限も無い）こと
