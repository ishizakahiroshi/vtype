# vtype

[English](README.md) | 日本語

> この日本語版は英語版 [README.md](README.md) の訳です。内容が食い違うときは英語版が正です。

Web ページでも、パソコンのどのアプリでも、テキスト欄に声で入力できます。

vtype には 2 つの形があります。別々のプログラムで、どちらも片方だけで動きます。

- **[ブラウザ拡張機能](#ブラウザ拡張機能)**（Chrome 用・
  [Chrome ウェブストア](https://chromewebstore.google.com/detail/vtype/nngfilimeplngdjdmgkddlhbdjpmikgn)で公開中）。
  **使えるのは Chrome で開いた Web ページの中だけです。** ページに見えているテキスト欄には、右端の
  すぐ外側にうっすらとした小さなマイクが付きます。押して話すと、話している間にもその欄のカーソル位置へ
  文字が入っていきます。検索ボックスでも、問い合わせフォームでも、書式付きのメッセージ本文でも、
  文字を入力できる欄であればそのまま使えます。
- **[vtype デスクトップ版](#デスクトップ版)**（Windows・macOS・Linux 用・リリース準備中）。
  **ブラウザも含め、パソコンのどのアプリでも使えます。** どのアプリ（テキストエディター、チャット、
  ターミナルなど）でもショートカットを押して話せば、その内容がそこへ入力されます。

どこで使えるか:

| 入力したい場所 | ブラウザ拡張機能 | デスクトップ版 |
|---|---|---|
| Chrome で開いた Web ページ | ✅ | ✅ |
| ほかのブラウザ（Firefox など）で開いた Web ページ | ❌ Chrome のみ | ✅ |
| ブラウザ以外のアプリ（テキストエディター、チャット、ターミナルなど） | ❌ | ✅ |
| 始め方 | 欄の横のマイクを押す | ショートカットか、マイクアイコンを押す |
| 必要なもの | Chrome 116 以降 | Google Chrome（裏で動かすため） |
| 公開状況 | Chrome ウェブストアで公開中 | リリース準備中 |

どちらも音声認識を自前では持っていません。Chrome には音声認識（Web Speech API）が組み込まれていて、
vtype はそれを借りています（デスクトップ版は、そのために Chrome を裏で動かします）。そのため API キーも
アカウントも要らず、話せる時間の上限もありません。利用時間を数えて追加分を売る拡張機能もありますが、
そうしないことが vtype の存在理由です。

## ブラウザ拡張機能

### インストール

[Chrome ウェブストア](https://chromewebstore.google.com/detail/vtype/nngfilimeplngdjdmgkddlhbdjpmikgn)
を開いて **Chrome に追加** を押してください。続いて開くタブでマイクの許可を一度だけ求められます。
そこで許可すれば、以後どのサイトでも聞かれません。更新は Chrome が自動で行います。

Chrome 116 以降が必要です。Firefox にはまだ対応していません。Firefox は `SpeechRecognition` を
無効にした状態で出荷されていて、offscreen document も持たないため、独自の認識エンジンが別に必要です。

### ソースから入れる

自分で変更したものや、まだストアに届いていない修正を試すときは、ビルドして
パッケージ化されていない拡張機能として読み込みます。

```sh
pnpm install
pnpm -F vtype-core build
pnpm -F vtype-extension build
```

`chrome://extensions` を開いて **デベロッパー モード** をオンにし、**パッケージ化されていない拡張機能を読み込む**
を押して `packages/extension/dist` を選びます。動く vtype が 1 つだけになるよう、先にストア版を
オフにしておいてください。詳しい手順と、読み込んだ後に確かめることは
[`packages/extension/README.md`](packages/extension/README.md)（英語）にあります。

### できること

- 画面に見えているすべてのテキスト欄に、うっすらとしたマイクが出る（使っている欄だけに絞ることもできる）
- 話すそばから、カーソルの位置へ文字が入る。前後の文字はそのまま残る
- 3 つのボタンが並ぶパネル: 欄を空にする、ページを送信する、録音を始める / 止める
- 録音中は波形が動くので、声が届いているかがその場で分かる
- 日本語 IME で変換している間は、書き込みを待つ
- サイト自身のボタンとマイクが重なるときは、ドラッグでずらせる。ずらした位置はそのまま覚えている
- ツールバーのアイコンでサイトごとに vtype を切れる。切ったサイトの一覧は設定ページで管理できる
- パスワード欄にはマイクを出さない。読み取り専用の欄と無効化された欄にも出さない
- 録音の様子がおかしいとき用の診断ログ（取るかどうかは自分で選ぶ）。記録するのは時刻と回数で、
  話した言葉は記録しない
- 英語と日本語に対応し、ブラウザの言語に合わせて切り替わる。言語を足すのはファイル 1 本で済む:
  [言語の足し方](packages/extension/README.md#adding-a-language)（英語）

## デスクトップ版

vtype デスクトップ版（Windows・macOS・Linux）は、同じ音声認識をブラウザの外で使えるようにします。
どのアプリ（テキストエディター、チャット、ターミナルなど）でもショートカットを押して話せば、
その内容がそこへ入力されます。拡張機能は要りません。デスクトップ版は Google Chrome を裏で起動し
（いつも使っている Chrome のプロファイルではなく、専用のプロファイルで）、Chrome の音声認識を
使います。文字は前面にあるアプリへ入力されます。**Google Chrome が入っている必要があります。**

### インストール

リリースの準備中で、npm・Microsoft Store・Homebrew・GitHub Releases を並行して進めています。
公開後は次の方法で入れられます。

- Windows: Microsoft Store
- macOS: Homebrew の tap（`brew install ishizakahiroshi/tap/vtype`）
- Linux: GitHub Releases の `.deb`
- どの OS でも: npm（`npm i -g @ishizakahiroshi/vtype`）

パッケージの作り方は [`packages/native/README.md`](packages/native/README.md)（英語）にあります。

**Mac・Linux をお持ちの方へ（お願い）。** 正直に書いておきます。申し訳ないのですが、macOS 版と
Linux 版は、コードを読んでのバグの確認と、自動のビルドとテスト（CI）しかできておらず、実機ではまだ
動かせていません。Mac や Linux をお持ちの方に試していただけると、とても助かりますし、とても嬉しいです。
動いた・動かなかったのどちらでも、[issue](https://github.com/ishizakahiroshi/vtype/issues) で
教えてください。

### できること

- どこからでもショートカットで: Windows と Linux は Ctrl+Alt+Space、macOS は Control+Option+V
  （`vtype settings` で変えられる）
- 画面の右下あたりに小さなマイクアイコン。トレイ / メニューバーのアイコンにも同じ操作がある
- 入力モードは 3 つ（通常・英語・カタカナ）で、変えるまでそのまま
- テンプレート: マイクの左上のボタンで保存した文章の一覧が出て、選んだものが入る。どのアプリでも
  文字を選んだままマイクを右クリックし「選択中の文字をテンプレートに登録」を選ぶと、保存できる
- 入力欄にカーソルがないときに話した言葉は、前面にあるものへは入力しない。マイクの上の吹き出しに
  残り、**コピー** と **入力欄に入れる** が付く（欄をクリックしてから「入力欄に入れる」を押す）
- パスワード欄には何も入力しない（Linux では、デスクトップのアクセシビリティ機能が
  パスワード欄だと判別できる範囲で）
- 実験中の機能で、既定はオフ（Windows と macOS）: 今いるテキスト欄の横にマイクを出す

### はじめて使うとき

1. vtype を起動します。Microsoft Store から入れた場合は、スタートメニューから開きます。zip の場合は
   `vtype.exe` をダブルクリックします（または `vtype` を実行）。npm・Homebrew・tar.gz の場合は、
   ターミナルで `vtype` を実行します（tar.gz は展開したフォルダで `./vtype`）。`.deb` の場合は、
   次のサインインで起動します（または `vtype` を実行）。動いている間にもう一度起動すると、
   設定ページが開きます。
2. ショートカット（またはマイクアイコン）を押します。小さな Chrome の窓が 1 回だけ開くので、
   vtype が何をどこへ送るかを読んで **同意して始める** を押し、マイクを許可します。窓は自動で閉じ、
   以後 Chrome は画面の外で動きます。
3. 同じ窓に **サインインしたら vtype を起動する** があり、最初はチェックが入っています。そのままに
   すると以後 vtype は OS と一緒に起動し、外すと起動しません（Store 版と `.deb` 版は最初から OS と
   一緒に起動し、チェックを外すとそれが止まります）。後から変えるときは、設定ページで
   デスクトップ版の設定の先頭にある同じチェックボックスを使います。
   コマンドラインでは、`vtype install` でオンになり、GNOME ではショートカットも追加されます
   （窓と設定ページからは追加されません）。`vtype uninstall` はオフにして、そのショートカットを外し、
   vtype を終了します。

vtype を移動したり、別の場所に入れ直したりしたときは、その場所から 1 回起動してください。vtype は
起動するたびに、別の場所の vtype を起動するサインイン時の登録があれば、今動いている vtype を指すように
書き換えます。登録が無いときに新しく足すことはしません。Store 版は常に自分自身を起動します。

`vtype settings`（またはトレイメニューの **設定を開く**）で、その Chrome に vtype 自身の設定ページが
開きます。ショートカット、入力モード、置き換え表、文字の入れ方を変えられます。

### コマンド

```sh
vtype toggle          # 音声入力を始める。動いていれば止める
vtype start           # 始める
vtype stop            # 止める
vtype mode kana       # normal | en | kana
vtype status          # 音声認識のページがつながっているか、音声入力中か
vtype settings        # 設定ページを開く
vtype diag            # 診断情報（話した言葉は含まない）
```

コマンドは動いているアプリへ指示を送るので、どのランチャーからでもキーに割り当てられます。
たとえば Windows の AutoHotkey v2 では次のようにします。

```ahk
^!k::Run "vtype mode kana"
```

GNOME では、`vtype install` が Ctrl+Alt+Space をカスタムショートカットとして追加します
（Wayland ではアプリが自分でキーを横取りできないため）。**設定 > キーボード > カスタムショートカット**
に `vtype toggle` を実行するショートカットを自分で作っても、同じように動きます。

### OS ごとの注意

- macOS: **システム設定 > プライバシーとセキュリティ > アクセシビリティ** で vtype を許可してください。
  許可しないと、ほかのアプリへ文字を入力できません。実行ファイルに署名していないため、更新の後に
  もう一度許可が要ることがあります。
- Linux の Wayland: アプリからキー入力を送ることが許されていないため、vtype はデスクトップの
  リモートデスクトップ用ポータルを通して頼み（デスクトップが許可を求めてきます）、だめなら
  `ydotool`（英字のみ）を試し、それもだめなら文字をクリップボードに入れて貼り付けるよう知らせます。
  Wayland では浮かぶマイクアイコンは出ないので、トップバーのアイコンを使ってください。

## 不具合の報告

拡張機能の設定ページとデスクトップ版のトレイメニューにある **不具合を報告** を押すと、OS と版を埋めた
GitHub の新しい issue がブラウザで開きます。自分で送信するまで、何も送られません。デスクトップ版では、
トレイメニューの **診断情報をコピー** が OS・版・設定・最近のエラーをクリップボードに入れるので、
それを貼り付けてください。音声や話した内容は含みません。

## プライバシー

vtype は、声をブラウザ自身の音声認識へ渡します。**Chrome では、ブラウザが音声を Google の
音声認識サービスへ送ることで認識が行われる**ため、話した内容は Google に届きます。話す前に
知っておいてほしいのはこの点で、マイクの許可ページでも、許可するボタンの上にそう書いています。

それ以外にブラウザの外へ出るものはありません。vtype は開発者へ何も送らず、送り先のサーバーも
持っていません。個人情報、閲覧履歴、ページの内容、利用状況の分析データはどれも集めず、
文字起こしの履歴も残しません。デスクトップ版もネットワークへは何も送りません。最初の録音の前に
同意を求め、その後は同じように Chrome の音声認識を使い（そのため話した内容は Chrome を通じて
Google に届きます）、やり取りするのは自分のパソコンの中のその Chrome だけです。全文は
[PRIVACY.md](PRIVACY.md) にあります。

拡張機能の設定ページの最後と、デスクトップ版のトレイメニューにある **vtype について** でも、
版・開発者・ソースコード・ライセンスとあわせて同じことを書いています。

## リポジトリの構成

| パス | 中身 |
|---|---|
| `packages/core` | `vtype-core`: 認識エンジン。画面には何も描かず、表示はすべて呼び出し側が持つ |
| `packages/extension` | Chrome MV3 拡張機能。ビルドすると `dist/` ができ、それを読み込む |
| `packages/extension/_locales` | 利用者が読む文字列すべて。言語ごとに 1 ファイル（[足し方](packages/extension/README.md#adding-a-language)） |
| `packages/native` | vtype デスクトップ版: Windows・macOS・Linux 共通の Rust プログラム 1 本と、そのパッケージ作成（[詳細](packages/native/README.md)） |
| `scripts/` | 検査、ストア用パッケージ作成、secrets-scan のゲート |
| `docs/store/` | Chrome ウェブストアの掲載文、プライバシーポリシー、版ごとの提出メモ |
| `spike/mic-permission` | マイクの許可の仕組みを確かめた使い捨ての試作。配布物には入らない |

開発用のコマンド（リポジトリのルートで実行）:

```sh
pnpm -r build        # core が先、次に拡張機能（拡張機能は core の dist/ を使う）
pnpm -r typecheck
pnpm -r test
```
